# 逐份審閱與訪談彙整表 Review Workflow

同一個專案有多份逐字稿時，**一份一份和使用者確認**；每確認一份，就整理進同一張**訪談彙整表** `interview-table.csv`。全部確認完，才進入編碼分析（步驟 2 起）。

為什麼要逐份停下來：清理錯誤會往後傳 —— 第一份確認過的專有名詞與話題清單，會直接套用到後面每一份。早一份發現錯，後面就少錯好幾份。

## 什麼時候用

| 情況 | 做法 |
|---|---|
| 一次給 ≥2 份同一專案的逐字稿 | **預設**走逐份審閱 |
| 使用者說「直接跑完」「不用逐份確認」 | 不停，清理全部後照一般流程 |
| 只有 1 份，但使用者說之後還有 | 照樣建總表，之後追加 |
| 輸出資料夾已經有 `interview-table.csv`（同一專案追加） | 接續編號（已有 P01–P03 就從 P04 起），沿用既有的專有名詞表與話題清單 |

## 流程

```
開始前    確定話題清單（有訪綱用訪綱；沒有就從第一份歸納，在第一個停點請使用者確認）
每一份    清理（步驟 1）→ 審閱停點，等使用者回覆 → 套用修正 → 寫進總表 → 下一份
全部完成  總表完整 → 問使用者要不要進入分析（步驟 2–11）
```

### 開始前：話題清單

總表的每一列＝一位受訪者 × 一個話題。**全案用同一套話題**，表格才比得起來。

- **有訪綱**：每題（或每個題組）＝一個話題，帶題號。
- **沒有訪綱**：讀完第一份清理稿，歸納 3–12 個話題，在第一個停點請使用者確認。
- 話題名稱寫**談了什麼**，不寫結論：✅「排程後的確認」 ❌「不信任系統」。
- 話題清單寫進 `cleaned/cleaning-overview.md`，清理步驟 6 的話題分段也用這一套。
- **後面出現新話題**：可以加。加的時候回頭檢查已確認的那幾份清理稿：有談到 → 補列，並在當下的停點請使用者確認；沒談到 → 補一列「—（未談到）」。

### 每一份的審閱停點

清理完一份就**停下來**，給使用者看下面五塊，然後等回覆：

1. **清理摘要** —— 各類改動的數量，附清理稿位置。
2. **待確認** —— 本份所有待確認項目，不分等級，都在這裡問。
3. **新加入專有名詞表的詞** —— 請使用者確認寫法；確認後套用到後面每一份。
4. **話題清單的變動** —— 第一份、或有新增話題時才有。
5. **要寫進總表的列** —— 這位受訪者在每個話題各一列：話題｜重點摘要｜代表引句｜回合。

結尾固定問：「以上確認後，我把這 N 列寫進總表，接著處理 P0X。有要改的直接說。」

使用者回覆後：

- 回「OK」「下一份」→ 這一份的列全部標 `已確認`。
- 有修正 → 改清理稿與列內容，被改到的列標 `已修正`，在 `備註` 記下改了什麼。
- 使用者補充的背景（例如受訪者的團隊規模）寫進 `備註`，標明「研究者補充」—— 那不是受訪者說的話。
- 暫時答不出來的 → 標 `待確認`，照樣處理下一份；最後一份完成時一起再問一次。
- 更新 `cleaned/cleaning-overview.md`（專有名詞表、去識別化規則、話題清單、待確認總表）。

### 重點摘要怎麼寫

- **1–2 句轉述，不加引號** —— 引號只留給代表引句。
- **只寫他說了什麼、做了什麼，不寫解讀**（解讀是步驟 6 之後的事）。
  - ✅「每次排程後都開無痕視窗到前台確認；起因是一次排了卻沒上、客戶當天打來」
  - ❌「他不信任系統」← 這是解讀
- 前後說法不一時兩種都寫（「先說……；後段說……」），不替他選一個。
- 代表引句依引句規則：逐字、從清理稿取（見 `insight-quality-rules.md` 第六節）。回合可列多個。
- 該話題沒談到：重點摘要寫「—（未談到）」，引句與回合留空。沒問到不等於沒想法 —— 這些列在步驟 10 直接成為涵蓋率表的 `no_data`。

## 訪談彙整表 `interview-table.csv`

### 欄位

| 欄位 | 內容 | 例 |
|---|---|---|
| 代號 | 受訪者代號 | P01 |
| 角色 | 概括到不能指認 | 內容編輯 |
| 年資 | | 3 年 |
| 使用頻率 | 不知道就留空，不要猜 | |
| 訪談日期 | | 2026-09-02 |
| 話題 | 話題清單裡的名稱 | 排程後的確認 |
| 訪綱題號 | 有訪綱才填 | Q3 |
| 重點摘要 | 1–2 句轉述 | 每次排程後都開無痕視窗到前台確認…… |
| 代表引句 | 逐字，可空 | 「那次之後我就每次都自己再確認一次。」 |
| 回合 | 多個用 `; ` 分隔 | P01-T010; P01-T012 |
| 審閱狀態 | 已確認／已修正／待確認 | 已確認 |
| 備註 | 修正紀錄、研究者補充 | |

排序：依代號；同一位受訪者內依話題清單順序。要橫向比較同一個話題，在試算表裡依「話題」篩選或排序即可。

### 檔案規則

- **編碼 UTF-8 with BOM。** 沒有 BOM，Windows 的 Excel 會把中文開成亂碼。
- **用 CSV 函式庫寫，不要手動拼字串** —— 引號與逗號的跳脫交給函式庫。例如 Python 的 `csv` 模組搭配 `open(path, "w", encoding="utf-8-sig", newline="")`；PowerShell 的 `Export-Csv -Encoding utf8BOM -NoTypeInformation`。
- **每次都整份重寫**（既有的列＋新列），不要用附加模式 —— 附加時容易用錯編碼，BOM 也可能跑到檔案中間。已確認的列，**內容**不動。
- 每個欄位都用半形雙引號 `"` 包起來；欄位內的 `"` 寫成 `""`。
- 儲存格內不換行；多個項目用 `; ` 分隔。
- 第一列是欄位名稱，照範本 `templates/interview-table.template.csv` 一字不差。
- 可直接用 Excel 開、匯入 Google 試算表，或匯入 Notion 變成資料庫。
- ⚠️ 在 Windows 上用程式把中文**印到主控台**時可能顯示成亂碼（主控台編碼不是 UTF-8）—— 那是顯示問題，不是檔案壞了。要確認檔案，看前三個位元組是不是 `EF BB BF`，或直接用 Excel 開；不要因此重寫檔案。

## 範例（延續 `examples/worked-example.md` 的同一批資料）

沒有訪綱。第一份 P01 清理完後的停點：
