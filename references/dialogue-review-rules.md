# 全文問答審閱與意義單位選取

完整分析先讀整份對話，再形成單位，最後選報告引句。既有精選句、舊碼表、關鍵字搜尋或長度門檻都不能取代全文審閱。自動化只協助來源定位、匯出與核對，不替分析者決定哪些回答有意義。

## 怎麼決定納入

- 依相鄰問答辨認誰在說什麼、指向哪個任務、對研究問題有何意義。納入行為、期待、理解、理由、條件、情緒、困難、解法、正面或中性評價、反例及改口。不可只挑負面或容易寫成洞察的內容。
- 短答案不等於無關：「有」「不會」「夠了」可能完整回答前一問。把必要問題放在脈絡欄，判斷是實質確認、否定，還是單純接話。長回答也可能只有主持人講解或操作過場。
- 不用字數、標點、固定句長、關鍵字命中、是否完整文法來判斷分析價值、話者歸屬或待審狀態。
- 排除無關的主持人發言、系統通知、純操作指令、社交過場。相關問題保留為上下文，不獨立編為受訪者觀點。受訪者明確同意主持人的引導性命題時，可保留為「引導後確認」，與自發主張分開。
- 同一回答被ASR斷成多行時合併；澄清插話前後若仍在解釋同一意思，可納入同一問答脈絡，但不把主持人文字混成受訪者逐字引句。獨立主張、改變情境或非相鄰回答應拆開。重複附和可連到既有單位，不能無痕刪掉，也不為湊數拆成多個人數。

## 完整句與原文是兩個欄位

預設保留逐字句；若使用者要求每列都是完整可讀句，可以使用情境補足重述，但必須同時交付：

1. `sentence`：完整、可獨立理解的重述，保留否定、條件、程度、不確定及改口；不得加引號冒充原話。
2. `sentence_type`：`verbatim` 或 `contextual_reconstruction_not_verbatim`。
3. `raw_sentence`：去識別化來源片段，不默默潤飾；多個片段用 ` ⟪…⟫ ` 分隔。
4. `source_turn`、`source_file`：各片段的來源；`context_turns` 指向整段問答，不能冒充每行都是受訪者發言。
5. `context_note`、`evidence_type`：補足依據、引導後確認、既往自述、當場回述、意見或假設。只有錄音／影像支持時才稱直接觀察。

補足只能明示上下文已有的主詞、對象、指涉。不能代填新理由、情緒、因果或把研究者方法警語寫成參與者說過的話。原文無法支撐完整解讀時才進Review Queue，具體寫不確定的詞、否定、話者或指涉，先嘗試相鄰問答澄清，不因短而待審。對話局部不清與局部可編碼可以並存。

## 情境與主題

使用者提供多情境時，以語意、任務及對話轉折判斷，按 `Scenario → Theme → Sub Theme → Initial Code` 組織。同一情境可有多主題、同一單位可多碼；跨情境／不確定情境獨立標示，不硬塞。主題分組不是互斥人口分群；不得把情境不同造成的偏好改變當矛盾人格。

## 涵蓋與完成條件

- 建立來源清單、排除名單、原檔雜湊和全文順序編號。全文每個來源片段都要有審閱結果、連到哪些單位／待核項及原因。
- `Source Coverage.csv` 保留原文字、`source_turn`、`review_decision`、`reason`、`linked_units`、`review_flags`。沒有獨立編碼不等於未知話者；混合對話行不等於全行受訪者證據。
- `Review Queue.csv` 只存確有未解問題的具體範圍、理由及所需確認；不得將所有未選長句批量標待審。
- 全文已閱讀≠全字稿已核音≠所有回答已完全可編碼。分開報來源片段、意義單位、編碼列、人數及待核範圍；缺碼不代表未提到。不能把新舊分段數直接當涵蓋率或品質高低。
- 代表引句在編碼完成後才選。每個洞察回查完整對話，掃描相反、條件式及少數意見。若尚有實質內容未逐段閱讀，不得聲稱完成全量審閱。

## Excel 與CSV

CSV不能保存篩選、凍結、分頁或樣式。要求篩選時另交 `.xlsx`，所有資料表每一欄皆使用原生Excel Table／AutoFilter、單層不合併表頭，凍結表頭，合理欄寬與換行。多情境可另作分頁／CSV，總表仍保留Scenario篩選。匯出後核對每張表的篩選範圍涵蓋所有欄和列，不能只把表頭塗色。統計快照須標明修改編碼後需重算，不假稱自動樞紐表。

## 虛構例子（不是研究證據）

主持人：「你要現在跳去詳情嗎？」受訪者：「不會。先讀完這裡。」

- 完整句：「我想先讀完目前內容，不要現在跳去詳情。」
- raw_sentence：「不會。先讀完這裡。」
- sentence_type：`contextual_reconstruction_not_verbatim`。
- 碼：閱讀完成前保留原頁；不是「短句無關」或「話者不明」。

主持人：「所以它很難用，對嗎？」受訪者：「對，但只在資料很多的時候。」

- 必須保留「資料很多」條件並標引導後確認，不能寫成自發的普遍負評。

主持人：「下一題請按開始。」受訪者：「好。」

- 程序性接話，保留來源涵蓋而不建立產品觀點；判準是上下文，不是「好」只有一個字。
