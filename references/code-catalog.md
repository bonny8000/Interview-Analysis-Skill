# 編碼維度型錄 Code Catalog

編碼維度（code dimension）= 在訪談資料裡，**值得被貼上碼的那一類東西**。它不是碼本身，是提醒你「這類東西你有沒有漏掉」的鏡頭。

## 它是安全網，不是答案表

下表 13 種**不是「碼就只有這些」**，而是 13 個**角度/鏡頭**，用法（A 法）：

1. **先自由發想**：先做完開放編碼，讓碼從這份逐字稿自己長出來。(主要來源)
2. **再掃這 13 種補漏**：看有沒有整個維度被漏掉（例如全程沒有任何 `non_use` 的碼，很可能是你沒注意到有人講了放棄的理由）。
3. **特有的直接加，標 `other`**。型錄是**下限不是上限**。

⚠️ **順序不可顛倒。** 先拿型錄去套逐字稿＝把資料塞進你預設的格子，那是 Track A 的框架套用，不是開放編碼。型錄只在事後掃漏用。

## 兩個鐵則

1. **碼要貼在「他實際說的內容」上，不要貼在你的解讀上。**
   - ✅ `current_workaround`：「我都先匯出成 Excel 再手動貼回去」
   - ❌ `needs_bulk_import`：← 這是你的結論，不是他的話
2. **痛點類的碼要標一個 `failure_mode`**（取自本檔最後一節），讓用語跨四份文件一致、好對照。

## 第一層：基本盤（13 種）

先自由發想，再對照下表掃漏（不適用的略過，不要硬湊）。

| code key | 中文 | 引導問句（怎麼從逐字稿找出這類碼） | 範例（設計工具訪談） |
|---|---|---|---|
| `goal_job` | 目標／任務 | 他來做這件事是想完成什麼？真正要交付的東西是什麼？ | 「我要在週五前給 PM 一版可以點的」 |
| `current_workaround` | 現行做法／土炮解法 | 現在實際怎麼做？用什麼東西湊？繞過了什麼？ | 「我都先截圖貼到 PPT 上標紅字」 |
| `pain_point` | 痛點 | 哪裡卡住、重做、要等、要問人？（**必標 `failure_mode`**） | 「每次存完都不確定同事看到的是不是最新的」 |
| `trigger_moment` | 觸發時機 | 什麼事發生會讓他想到要做這件事？從哪裡進來的？ | 「通常是 PM 在群組丟一句『可以看一下嗎』」 |
| `decision_criteria` | 決策準則 | 他怎麼選？比較了什麼？什麼是不能妥協的？ | 「能不能匯出成開發看得懂的格式最重要」 |
| `mental_model` | 心智模型 | 他**以為**它是怎麼運作的？（不論對錯） | 「我以為按分享就等於發布了」 |
| `expectation_gap` | 期待落差 | 他以為會怎樣 vs 實際怎樣？哪裡驚訝？ | 「本來想說一鍵就好，結果要設六個欄位」 |
| `emotion` | 情緒訊號 | 哪裡講到煩／爽／怕／不好意思／懶得？語氣變了嗎？ | 「講到要重新命名的時候他嘆氣」 |
| `constraint` | 限制 | 時間、預算、權限、裝置、組織規定卡住了什麼？ | 「我沒有管理員權限，每次都要找 IT」 |
| `tool_ecosystem` | 工具生態 | 前後接什麼工具？資料怎麼進來、怎麼出去？ | 「從 Notion 複製過來，最後要貼進 Jira」 |
| `collaboration` | 協作與角色 | 誰一起做？誰要核准？交接在哪裡斷掉？ | 「要等主管在 Line 上回一個 OK 才能發」 |
| `desire_request` | 明說的需求 | 他自己要求的功能／解法。**是資料不是結論** | 「你們就做一個批次匯出就好了啊」 |
| `other` | 其他 | 以上都不是、但這份資料特有的重要內容 | 視資料而定 |

## 怎麼挑

- **流程型訪談**（請他描述一次完整的工作）：一定會有 `goal_job`、`trigger_moment`、`current_workaround`、`collaboration`。
- **痛點挖掘型訪談**：`pain_point`、`emotion`、`expectation_gap`、`constraint` 會最密集。
- **選型／採購型訪談**：`decision_criteria`、`tool_ecosystem`、`trust_risk`（第二層）是主軸。
- **既有產品回訪**：`mental_model`、`non_use`（第二層）、`expectation_gap` 最有料。

不必每份逐字稿都湊滿 13 種；列出**這份資料裡真的有**的即可。寧可精準也不要灌水。

## 第二層：進階鏡頭（8 種，依資料性質選用）

這 8 類最常被漏掉，而且往往是洞察含金量最高的地方 —— 但不是每份逐字稿都要跑。

| code key | 中文 | 引導問句 | 範例 |
|---|---|---|---|
| `switch_moment` | 轉換時刻 | 什麼事讓他換掉舊方案／開始用這個？（JTBD 的關鍵） | 「就是那次檔案掉了之後我就改用雲端了」 |
| `non_use` | 不使用／放棄 | 哪些功能他知道但不用？為什麼停用？ | 「那個留言功能我知道，但沒人會看所以我不用」 |
| `frequency_scale` | 頻率與量體 | 多常做？一次處理多少？尖峰在什麼時候？ | 「一天大概 3 次，月底那週會到 20 次」 |
| `trust_risk` | 信任與風險 | 他怕什麼出錯？什麼讓他敢／不敢？出錯代價多大？ | 「我不敢用自動的，萬一改到客戶的正式版就完了」 |
| `learning_path` | 學習路徑 | 他怎麼學會的？誰教的？卡住時問誰？ | 「同事錄了一段影片給我，我到現在還在看那個」 |
| `context_env` | 實體情境 | 在哪做？什麼裝置？會被打斷嗎？有幾個螢幕？ | 「通常在會議中一邊開會一邊改，很容易被打斷」 |
| `contradiction` | 自我矛盾 | 他說的跟做的一致嗎？前後講法有沒有衝突？ | 說「不在意速度」但全程抱怨等太久 |
| `outlier_view` | 異例觀點 | 只有一個人這樣說、但可能指向真問題的觀點 | 只有 P07 提到無障礙需求，但那是法規風險 |

**依資料性質挑**：問到「為什麼開始用」→ `switch_moment`；問到既有功能 → `non_use`；要估算規模 → `frequency_scale`；涉及金錢/正式資料/不可逆操作 → `trust_risk`；新手 vs 老手比較 → `learning_path`；現場/行動情境 → `context_env`。

`contradiction` 與 `outlier_view` **每次都要掃**，它們是第 8 步反證掃描的主要來源 —— 見 `insight-quality-rules.md` 第四節。

## 失敗模式 failure_mode（`pain_point` 專用）

所有標成 `pain_point` 的碼，額外標一個 `failure_mode`。**這套詞彙與 user-story / user-flow / sitemap 完全相同**（四個 skill 各存一份相同型錄、不互傳檔案），目的是讓你同時看四份文件時名詞對得起來。

### 第一層

| failure_mode | 中文 | 在訪談裡長什麼樣 |
|---|---|---|
| `validation_error` | 輸入不合規 | 「它一直說格式不對，但沒講哪裡不對」 |
| `permission_denied` | 沒有權限 | 「我沒權限，每次都要找人開」 |
| `empty` | 空狀態 | 「第一次進去空空的，不知道要幹嘛」 |
| `loading_slow` | 處理中／等太久 | 「按下去要等很久，不確定有沒有在跑」 |
| `server_error` | 系統出錯 | 「有時候就會失敗，我也不知道為什麼」 |
| `network_timeout` | 網路中斷／逾時 | 「在外面網路不好，做到一半就斷了」 |
| `no_results` | 查無結果 | 「搜尋常常找不到，我知道那個東西明明在」 |
| `cancel_abort` | 中途放棄 | 「做到一半想取消，又怕前面做的不見」 |
| `unsaved_leave` | 未存就離開 | 「有一次沒存就關掉，整個下午白做」 |
| `conflict` | 並發／版本衝突 | 「同事同時在改，最後不知道誰的版本是對的」 |
| `session_expiry` | 登入逾時 | 「離開一下回來就被登出，填的都沒了」 |
| `partial_success` | 部分成功 | 「一次傳 10 個只成功 7 個，剩下的要自己找」 |
| `other` | 其他 | 視資料而定 |

### 第二層（依情境選用）

| failure_mode | 中文 | 在訪談裡長什麼樣 |
|---|---|---|
| `accessibility` | 可及性 | 「我同事用鍵盤操作，那個選單他跳不進去」 |
| `wizard_midstate` | 多步中途態 | 「填到第三步重整，前面全部要重填」 |
| `optimistic_rollback` | 樂觀更新回滾 | 「明明顯示成功了，過一下又變回去」 |
| `double_submit` | 雙重送出／冪等 | 「怕沒成功就多按一次，結果跑出兩筆」 |
| `race_condition` | 競態 | 「快速切換的時候，看到的是上一個的結果」 |
| `pagination_scale` | 大量資料邊界 | 「東西一多就找不到，列表也變很慢」 |
| `timezone_locale` | 時區／語系 | 「顯示的時間跟我這邊對不上」 |
| `stale_display` | 顯示過期／不同步 | 「不確定看到的是不是最新的那版」 |

## 與 user-story / user-flow 的關係

interview-analysis 與那三個 skill **各自獨立、不互傳檔案**，但共用同一套 `failure_mode` 詞彙。這裡**只要把痛點編碼 + 標 failure_mode**，不要替 user-story 寫成「身為X我想要Y」，也不要替 user-flow 把失敗支線畫出來 —— 那兩個 skill 會自己從 PRD 重新發想。
